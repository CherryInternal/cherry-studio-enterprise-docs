以下示例区分网关托管的远程 HTTP 服务和本地执行的 `stdio` 服务。

## 托管 HTTP：请求头密钥

在 **手动添加** 的 JSON 配置中填入以下结构。将示例地址、请求头和值替换为提供方指定的配置。保存后，网关托管该请求头凭据，调用方使用代理地址。

```json
{
  "name": "Team Search",
  "type": "streamableHttp",
  "baseUrl": "https://mcp.example.com/mcp",
  "headers": { "Authorization": "Bearer REPLACE_WITH_API_KEY" }
}
```

## 托管 HTTP：个人 OAuth

1. 在表单中选择 `streamableHttp`，填写提供方的 MCP 服务地址。
2. 如果提供方支持 DCR，选择 **OAuth 2.1（自动注册 / DCR）**。如果要求预注册应用，选择 **OAuth 2.1（预注册应用）**，登记表单显示的回调地址并填写应用凭据。
3. 将 **凭据范围** 设为 **个人账号** 并保存。成员打开 `/connections`，在跳转后的 MCP 服务器页找到服务并点击 **连接授权**。

OAuth 模式不需要在请求头中手动填入访问令牌。

## 🌐 Playwright (网页自动化)

赋予 AI 浏览网页、截图和抓取数据的能力。

* **依赖环境**：Node.js
* **适用场景**：联网搜索助手、新闻摘要助手。

```json
{
  "name": "Playwright",
  "type": "stdio",
  "command": "npx",
  "args": [
    "-y",
    "@modelcontextprotocol/server-playwright"
  ]
}
```

## 📂 Filesystem (本地文件系统)

赋予 AI 读写服务器特定目录的能力。

* **依赖环境**：Node.js
* **适用场景**：代码审计助手、日志分析助手。

<Callout type="error">
**安全警告**：请务必在 `args` 中指定具体的 **安全目录路径**（如下例中的 `/Users/admin/desktop`），切勿直接授权根目录 `/`，以防系统文件被误删。
</Callout>

```json
{
  "name": "Filesystem",
  "type": "stdio",
  "command": "npx",
  "args": [
    "-y",
    "@modelcontextprotocol/server-filesystem",
    "/Users/username/desktop/allowed-folder"
  ]
}
```

## 📡 Fetch (HTTP 请求)

赋予 AI 发送 HTTP 请求的能力。

* **依赖环境**：Python (使用 UV 包管理器) 或 Node.js
* **适用场景**：API 测试、简单的数据抓取。

```json
{
  "name": "Fetch",
  "type": "stdio",
  "command": "uv",
  "args": [
    "x",
    "mcp-server-fetch"
  ]
}
```
