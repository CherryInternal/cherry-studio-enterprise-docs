**Q1: 保存時に "JSON Parse Error" が出る**

* **原因**：JSON 形式が不正。
* **対処**：末尾のカンマや中国語引用符を確認。**JSON 形式化** で簡易修正できます。

---

**Q2: ツール呼び出しがずっと読み込み中/エラーになる**

* **`stdio` の主な原因**：コマンドを実行する環境に必要なランタイムがありません。ゲートウェイ管理の HTTP MCP は下記を参照してください。
* **対処**：
  1. Cherry Studio を実行しているホストに **Node.js**（`npx` 用、ダウンロード：https://nodejs.org/ ）または **Python**（`uvx` 用、ダウンロード：https://www.python.org/downloads/ ）があるか確認。
  2. ネットワーク接続を確認。初回 `npx` 実行時は npm からパッケージを取得するためタイムアウトに注意。

---

**Q3: MCP が有効か確認する方法**

* **確認方法**：
  1. **アシスタント管理** で MCP サーバーをテスト用アシスタントに紐付け。
  2. チャットでツール呼び出し命令（例：「desktop ディレクトリの test.txt を読み取って」）。

## ゲートウェイ管理の HTTP MCP

**ゲートウェイが `403` を返す原因は？**

サーバーの **ログ** で呼び出しの状態を確認します。API が `SSRF_BLOCKED` を返した場合は、SSRF ポリシーが接続先をブロックしています。この場合、セルフホスト環境の管理者は API サービスに `MCP_PROXY_ALLOWED_CIDRS` を設定できます。デフォルトは空で、制限対象の内部ネットワークへの接続はブロックされます。承認済みの MCP 接続先に必要な最小範囲の IP または CIDR のみをカンマ区切りで指定し、API サービスを再起動します。

**OAuth のリダイレクト URI が一致しない、または管理画面に戻れない場合は？**

セルフホスト環境では、`API_URL` と `ADMIN_URL` にユーザーがアクセスできる HTTPS のベース URL を設定します。例えば、`API_URL=https://api.example.com` の場合、リダイレクト URI は `https://api.example.com/mcp-oauth/callback` です。事前登録アプリの場合は、編集画面のリダイレクト URI をコピーして提供元に登録します。`ADMIN_URL` は認可後の戻り先です。

**個人接続を復旧するには？**

`/connections` を開き、移動先の MCP サーバーページで対象の接続を探します。**Disconnect** を選び、次に **Connect** で認可します。その後、ツールの呼び出しを再試行します。

**HTTP リクエストや SSE ストリームが切れる原因は？**

ゲートウェイの上流 HTTP リクエストは 30 秒、SSE のアイドル状態は 300 秒でタイムアウトします。上流の応答時間と SSE のハートビートを確認します。`/v1/mcps/` では、リバースプロキシが応答をバッファリングしないこと、読み取りタイムアウトが 300 秒以上であること、`Mcp-Session-Id` を両方向に転送することを確認します。
